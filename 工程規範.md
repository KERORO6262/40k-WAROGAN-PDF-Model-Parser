## Source vs Bundle

`index.html` loads `app.bundle.js`, not `app.js` directly. The bundle is a single concatenated file that lets users open the app without installing Node or running a build step.

**The bundle is committed to the repository intentionally.** Removing it would break the zero-install workflow for anyone who downloads the repo and opens `index.html`.

When you edit `app.js` or any file under `parser/`, you must also update `app.bundle.js` before committing. Failing to do so means users downloading the repository will run stale logic.

To rebuild the bundle, concatenate the source modules in dependency order and write the result to `app.bundle.js`. The exact command depends on your local toolchain; if a build script exists in the repository, prefer that.

## Development Workflow

1. Edit `./assets/js/app.js` for UI changes.
2. Edit files under `./assets/js/parser/` for parsing or export logic.
3. Open `index.html` in a browser to test interactively.
4. If the browser blocks `file:///` access, run a local server (see README).
5. Run the parser fixtures to verify correctness (see Testing below).
6. Rebuild `app.bundle.js` after source changes.
7. Commit both source and bundle together.

## Testing

Run parser fixtures with Node:

```powershell
node --input-type=module -e "import('./assets/js/tests/parserFixtures.js').then(({runParserFixtures})=>console.log(runParserFixtures()))"
```

Or run in the browser DevTools console:

```javascript
runWaroganParserFixtures()
```

Assertions to check after any parser change:

- `Death Cult Assassins` appears as 1 row with `Count` = `2` in grouped model view.
- `Death Cult Assassins` appears as 2 rows with `Count` = `1` each in individual model view.
- Switching modes updates the table, count badge, preview select, and all export outputs simultaneously.

## Git and GitHub Guidelines

The `.gitignore` is configured as follows:

- `*.pdf` — ignores all PDFs at the repository root and in personal working directories
- `!samples/**/*.pdf` — allows PDFs committed under `./samples/` for public test use
- `warogan-models.json`, `warogan-models.csv`, `warogan-models.html` — ignores locally exported files
- Standard ignores for OS metadata, IDE config, cache directories, and `node_modules`

Never commit a private roster PDF. If you need a publicly shareable test file, place it under `./samples/` and commit it there.

## Parser Architecture Notes

The parser works in two stages: text extraction and rule-based parsing.

**Text extraction** uses PDF.js to read the text layer from the user's PDF. No image recognition is involved; the parser only sees text that PDF.js can extract.

**Rule-based parsing** applies regular expressions and heuristic pattern matching to identify units, model groups, weapons, abilities, and keywords from the extracted text. Because WAROGAN does not produce machine-readable output (JSON, XML), the parser infers structure from positional and textual cues.

Heuristic matching means the parser sometimes cannot determine with certainty which unit or model an ability or keyword belongs to. When this happens, the item is surfaced as a **parser warning** rather than silently assigned or discarded. Reviewers should inspect warnings after parsing a new roster format.

If a WAROGAN format change causes widespread parsing failures, start by reviewing the raw text tab in the UI to understand what the new format looks like, then update the relevant regex patterns in `./assets/js/parser/`.

## Source 與 Bundle 的關係

`index.html` 載入的是 `app.bundle.js`，而不是直接載入 `app.js`。Bundle 是一個合併後的單一檔案，讓使用者不需要安裝 Node 或執行建置步驟，就能直接開啟應用程式。

**Bundle 刻意提交至倉庫中。** 移除它會讓所有下載倉庫後直接開啟 `index.html` 的使用者無法執行。

當你編輯 `app.js` 或 `parser/` 下的任何檔案時，提交前必須一併更新 `app.bundle.js`。若未同步更新，下載倉庫的使用者將會執行到舊版邏輯。

重建 bundle 的方式是依照依賴順序將 source 模組合併，並寫入 `app.bundle.js`。確切指令取決於你的本機工具鏈；若倉庫中已有建置腳本，優先使用該腳本。

## Parser 架構說明

Parser 分兩個階段運作：文字抽取與規則比對解析。

**文字抽取**使用 PDF.js 從使用者的 PDF 中讀取文字層。不涉及圖像辨識；parser 只能看到 PDF.js 能夠抽取的文字。

**規則比對解析**使用正規表示式與啟發式規則，從抽取出的文字中識別單位、模型群、武器、技能與關鍵字。由於 WAROGAN 不產生機器可讀格式（如 JSON、XML），parser 依靠位置與文字線索來推斷結構。

啟發式比對意味著 parser 有時無法確定某個技能或關鍵字屬於哪個單位或模型。這種情況下，該項目會以**解析警告**的形式呈現，而非靜默地進行指派或丟棄。解析新的 roster 格式後，應檢視所有警告。

若 WAROGAN 格式變更導致大範圍解析失敗，請先透過 UI 的「原始文字」分頁了解新格式的結構，再更新 `./assets/js/parser/` 中相關的 regex 規則。
